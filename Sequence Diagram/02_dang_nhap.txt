// Đăng nhập qua ba lớp FastAPI
// H: mô hình hóa từ HTML, có cụ thể hóa thiết kế
// Use case: U01
// Đây là mô hình đề xuất, không phải sơ đồ trích xuất từ backend đã chạy.
// Web ở đây là portal admin hoặc chủ quán, không phải yêu cầu đăng nhập của khách du lịch.
// Repository có thể đọc cả admin_users và roles. Kiểm tra mật khẩu, trạng thái tài khoản và tạo token nằm trong Service.
// Đây là luồng cookie cho PWA; tên hàm và cách tách repository là thiết kế đề xuất.

autoNumber on
colorMode pastel
styleMode plain
typeface clean

Web [label: "Web Admin hoặc Owner", color: blue]
Router [label: "Auth Router", color: orange]
Service [label: "Auth Service", color: purple]
Repo [label: "User Repository", color: green]
DB [label: "MongoDB", color: green]

Web > Router: Gửi email và mật khẩu
Router > Router: Kiểm tra định dạng bằng Pydantic
Router > Service: Yêu cầu xác thực tài khoản
Service > Repo: Tìm tài khoản theo email đã chuẩn hóa
Repo > DB: Đọc admin_users
DB --> Repo: Thông tin tài khoản hoặc không tìm thấy
Repo --> Service: Trả kết quả tìm kiếm
Service > Service: Kiểm tra password hash và trạng thái tài khoản
alt [label: "Thông tin không hợp lệ hoặc tài khoản bị khóa"] {
  Service --> Router: Kết quả xác thực thất bại
  Router --> Web: 401 với thông báo đăng nhập không thành công
}
else [label: "Thông tin hợp lệ"] {
  Service > Repo: Đọc vai trò và quyền hiệu lực
  Repo > DB: Đọc roles và quyền bổ sung
  DB --> Repo: Danh sách quyền
  Repo --> Service: Danh sách quyền hiệu lực
  Service > Service: Tạo access token và refresh token có hạn
  Service --> Router: Token và thông tin tài khoản an toàn
  Router --> Web: 200 và cookie HttpOnly cùng thuộc tính bảo vệ
  Web > Web: Điều hướng theo quyền và trạng thái xác minh
}
